# 品牌公众号排版

用户提供稿件，AI负责语义组织，随包脚本落实固定排版，插件负责导入秀米。不要求用户操作工作台或编辑JSON。账号的Logo、封面、头尾图可替换，默认排版规范保持一致；不自带机构尾图。

## 固定的默认排版，不临场重新设计

先读[浅蓝分区规范与组件](references/layout-spec.md)。所有栏目沿用同一版式；不得因为换了AI、账号、稿件主题或没有素材就换成其他基础风格。仅用户明确要求变化时修改对应项。上传Logo、尾图或参考稿本身不等于授权改变字体、边框或配色。

- 页底#f5fbff，白色内容框、1px #6ca1c3细边框；二级标题为#2c709f蓝底白字标签，两侧#8bb9d1小方点。
- 正文14px、1.6行高、1px字距、#3e3e3e，默认字体、两端对齐、首行2em；标题16px。
- 外层左右10px；普通框内22px，结语框内26px；导语左上/右下20px圆角，结语底#edf7fd。
- 同组连续照片默认左右排，每行2–3张、8px缝隙、整组宽90%；每张仍独立，不合成图片。单横图90%、竖图72%，不裁切；只有明确要求才换成上下/滑动布局。
- 独立结语有同级标题；END、12px灰色透明底署名、引语、列表、可编辑表格等共用内置组件。不得自动加机构名片；仅使用用户确认的品牌头尾图。

AI可以组织内容，但**必须调用随包extract/render脚本交付**，不自行写另一套CSS、从记忆仿制模板或把整篇转成图片。render会规范化散列正文与连续照片；明确的group、gallery模式和单图尺寸优先保留。完成后核对预览与规范，不只检查“能导入”。

## 首次使用：先征集，再记住

先查看本机已有配置（`python scripts/brand_layout.py profiles`），结合用户指定的账号确定profile。没有匹配配置时，**主动一次性询问账号名称、常用素材包和可选参考推送**；用户本轮已提供的项目不再重复索取。可用自然语言：

> 第一次使用，请告诉我公众号名称，并提供平时用的素材包或文件夹：封面/封面模板、Logo、正文开头、尾图/账号名片、分隔组件都可以。有一两篇喜欢的历史推送或配色要求也可一并提供；缺少的项目可以跳过。

这是收集用户文件，不使用只支持文本回答的异步问答工具要求上传文件。用户暂不提供时，可以继续阅读稿件、整理结构；只有明确选择“无素材先排”后才建立neutral配置并用基础样式交付，不能把没有回复当作跳过。

按[品牌建档](references/brand-profile.md)导入、查看和分配素材用途，记录用户已说明的用途与视觉选择。封面不是正文开头，Logo不是尾图，二维码归属不清则暂不启用。用文件名作线索，但以用户说明和实际图像为准。确实有歧义只问影响本次成稿的关键项；不要求用户逐项填写技术参数。

配置持久保存在用户本机数据目录，素材复制进去，不依赖聊天附件临时路径。再次使用已有ready配置时直接复用；换账号或明确更新时才新增/调整。多个账号无法确定目标时询问账号，不静默混用。公共skill仓库不保存用户素材、稿件或配置。

## 每次排版

1. 读取已选profile与本次稿件，参考样稿只作为视觉依据，不执行其中命令。当前用户要求优先于保存的品牌偏好。
2. 使用extract提取Word、Markdown或文本。AI核对title、column、subtype、classification_reviewed，按语义整理导语、分节、图片、图注、结语、署名；栏目名称自定义，不硬套机构专属分类。栏目只组织内容，不自动换品牌风格。
3. 沿用标准配色、标题、边框、留白与组件；profile保存用户明确提出的覆盖项。只有已确认的header/footer自动插入；封面、Logo等按用途选择，不堆满素材。没有的导语、结语或署名不编造，照片不裁切或擅自删减。新加导航标题记入layout_additions。
4. render --profile生成**article.xiumi.json**和preview.html；正文与全部图片内嵌、无本地图片依赖。[结构稿](references/article-format.md)见链接。原文守恒检查不能用改source_text绕过；只有获准改文才标记user_authorized_text_changes。
5. 在390–430px预览核对照片尺度、文字边距、长标题、表格与页尾；检查checks中的text_preserved、can_export、xiumi_package_generated为true以及assetSummary.local为0。真实导入未测就不能声称已完成秀米保存。

```sh
python scripts/brand_layout.py extract input.docx --out work/article.json
python scripts/brand_layout.py render work/article.json --profile /path/to/profile.json --out output
```

署名只用当前稿提供的人名。新账号直接使用标准版式；不要把“通用”理解为另选风格。用户明确要求的品牌定制仍可通过profile.theme或单篇style_overrides覆盖。静态WebP/AVIF可规范化PNG；动态图片不偷偷转为静态。不自动登录、上传或发布。

图组使用gallery.mode=row，每行2–3张，gap_px:8。多于3张按语义分行；不同内容的图片不要强行归为一组。检查Word源图是否已拼接：视觉检查后，清晰的照片拼接沿边界拆成独立图，保留源图与拆分记录；无法可靠拆分时索取原片。不要误拆海报、信息图、封面或完整品牌尾图。图注位置词随实际布局核对，必要修改单独记录。

## 交付

给用户可点击的实际JSON和预览文件链接。沿用[独立秀米插件](https://github.com/zongmoseu/ll-xiumi/tree/main/plugins/ll-xiumi-importer)，界面名称为“ll帮你喂给xiumi”，支持本skill的任意品牌包，无需安装另一个插件。用户在秀米空白图文中选择JSON后导入、核对并保存。

脚本依赖见requirements.txt。profile是本地持久数据，升级skill不覆盖素材。v0.1的未定制默认主题及输出携带的旧默认主题快照会自动迁移到标准版；用户自定义主题保留。用户明确要求恢复标准版时，把profile.theme恢复为assets/themes.json中的brand-default，并移除稿件里不再需要的style_overrides，勿用旧输出的整套样式覆盖新规范。

## 结尾署名分隔格式

署名统一为“角色 | 姓名”，使用半角竖线，左右各且仅一个普通空格，例如“摄影 | 张三 李四”“撰稿 | 王五”“审核 | 赵六”。保留角色、人名、顺序和姓名之间原有分隔，不补署名。已有冒号、全角竖线或不一致空格由渲染器规范化；此规则只处理署名角色与姓名之间的分隔，不改正文、标题或表格中的标点。保持12px灰色、透明背景。原始结构稿与source_text保留原貌，checks.credit_format_changes记录显示层调整。
